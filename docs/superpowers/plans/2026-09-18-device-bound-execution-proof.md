# 设备绑定执行证明实施计划

## 目标

让“服务端下发的加密核心 + 执行票据”不能仅凭复制 artifact、改名或复制票据在另一台设备上复用。

## 实施步骤

- [x] 先增加 guest runner 的失败测试：缺少设备证明时，在 Docker 操作前拒绝。
- [x] 在客户端收到服务端签发的 grant 后，使用 DPAPI 保护的设备私钥对精确 grant payload 签名。
- [x] 在服务端消费 grant 前，用注册设备公钥验证设备证明；缺失或错误证明不消费 JTI。
- [x] 增加同设备有效证明、缺失证明、错误设备证明和 runner 缺失证明回归。
- [x] 运行 guest、授权服务和 Tauri 相关测试，并记录证据。

## 边界

设备证明提高了跨设备复制的门槛，但不能消除本机管理员/root/调试器在合法运行期间读取设备私钥或 runner 明文的风险；最高价值算法仍应保留在服务端。
