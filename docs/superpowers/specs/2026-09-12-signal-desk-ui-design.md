# Signal Desk UI Design

日期：2026-09-12

## 目标

将 Redroid Device Center 从“多个页面各自堆叠控件”整理为一个紧凑、可扫描、可持续操作的设备工作台。重点解决设备详情页中控制、文件、应用、日志、设置等 Tab 的层级混乱、模块边界不一致、滚动区域失控和操作入口重复问题。

本次改造只调整前端视觉结构、布局和交互呈现，不改变设备服务、命令参数、状态模型、存储键、路由和既有动作回调。

## 设计方向

产品对象是给开发者和设备运维人员使用的 Android / Redroid 控制台。页面的单一任务是：快速判断设备状态，然后在同一上下文中完成控制或维护。

采用 **Signal Desk / 设备工作台**：

- 页面使用模块、规则和标题带表达层级，不用大量浮动卡片表达层级。
- 默认使用纵向工作流；只有内容自身需要并列时才使用局部横向布局。
- 设备状态、连接状态、动作状态使用相同语义颜色和同一套状态标识。
- 让“当前 Tab 的工作区”成为页面视觉中心，其他信息退到辅助模块。
- 长内容在所属工作区内部滚动；页面滚动只承担跨模块浏览。

## 视觉令牌

### 色彩

| 令牌 | 浅色 | 用途 |
| --- | --- | --- |
| `--canvas` | `#E7ECEE` | 应用底色 |
| `--surface` | `#F8FAFB` | 工作区底色 |
| `--surface-soft` | `#EEF2F4` | 标题带、工具栏 |
| `--surface-tint` | `#F3F6F7` | 输入、空状态、次级区域 |
| `--ink` | `#17242D` | 主文字 |
| `--muted` | `#687983` | 辅助文字 |
| `--line` | `#C9D4D9` | 普通分隔线 |
| `--line-strong` | `#AABBC3` | 主要分隔线 |
| `--accent` | `#285FCA` | 主操作、当前 Tab、焦点 |
| `--mint` | `#168562` | 在线、成功、可用 |
| `--warning` | `#B87516` | 等待、未授权、需处理 |
| `--danger` | `#C9515D` | 离线、失败、破坏性动作 |

深色主题保留同一语义映射，只调整亮度和对比度。禁止为单个页面重新发明颜色。

### 字体与几何

- 页面标题：`Bahnschrift` / `Segoe UI`，紧凑字距，最多两级标题。
- 正文：`Segoe UI Variable`、中文回退到 `Microsoft YaHei`。
- Serial、IP、路径、命令、日志：`Cascadia Code` / `Consolas`。
- 间距节奏：`4 / 8 / 12 / 18 / 24px`，不再混用随意的内联间距。
- 普通模块圆角 6px，输入和按钮 6px，状态徽标可使用胶囊形。
- 模块不使用大阴影；只保留悬停和浮层所需的轻微层次。
- 标题带高度控制在 34～38px，工具栏高度控制在 32～40px。

## 全局页面框架

所有主页面统一为以下结构：

```text
┌ brand / primary navigation ─────────────────────────────── settings ┐
├ page title / subtitle / page actions ────────────────────────────────┤
├ context strip or status notice ───────────────────────────────────────┤
├ module heading ───────────────────────────────────────────────────────┤
│ module body                                                         │
├ module heading ───────────────────────────────────────────────────────┤
│ module body                                                         │
└ status bar ──────────────────────────────────────────────────────────┘
```

实现要求：

- `AppLayout`、顶部导航、页面标题、状态栏保持统一高度和对齐基线。
- 页面不再依赖页面级 `margin` 拼接视觉层级，模块之间统一使用 8～12px 间隔或分隔线。
- `Card` 继续兼容现有业务组件，但在详情工作区中通过 `detail-module` 样式呈现为无浮夸阴影的模块。
- 页面、表格、终端、文件列表各自声明滚动边界，禁止子元素把页面撑出不可控的外部滚动条。
- 所有操作按钮统一为“主操作 / 次操作 / 文字操作 / 危险操作”四级，不重复使用相同视觉权重。

## 设备详情信息架构

### 固定上下文栏

设备详情页顶部保留设备身份上下文，但重排为三层：

```text
返回  设备名称                         在线 / 离线   连接 / 启动  刷新  更多
      serial · Android 版本 · 镜像摘要
──────────────────────────────────────────────────────────────────────
概览     控制     文件     应用     日志     设置
```

- 返回和设备身份左对齐，设备动作右对齐。
- 状态使用“圆点 + 文本”，不再用多个互相竞争的徽标。
- Tab 只保留一条底部活动线，禁用状态只降低对比度并保留原因提示。
- Tab 采用图标 + 文本 + 必要时的状态提示；不把在线提示重复写进每个按钮标题。
- 当前 Tab 记忆逻辑继续使用现有 `sessionStorage` 键。

### Tab 工作区通用结构

每个 Tab 都使用相同的工作区壳层：

```text
当前区域标题                         当前区域操作
区域说明 / 状态摘要
────────────────────────────────────
主要工作模块
────────────────────────────────────
辅助模块（可折叠或内部滚动）
```

需要新增稳定的结构类名：

- `detail-shell`
- `detail-context`
- `detail-tabbar`
- `detail-workspace`
- `detail-workspace-head`
- `detail-module`
- `detail-module-head`
- `detail-scroll-region`

这些类只负责布局和视觉，不承载设备业务状态。

### 概览 Tab

- 顶部是一条“设备摘要带”：名称、Serial、在线状态、Android 版本、镜像。
- 设备字段整理为连续信息行，按“身份 / 连接 / 运行 / 容器”分组。
- 每组使用标题带和细线区分，不用四个独立卡片。
- 复制 Serial、复制全部信息、打开卷、打开容器和跳转其他 Tab 保持原动作。
- Root、LSPosed、SU 等高级能力作为概览底部的辅助模块；离线时不占空白高度。

### 控制 Tab

- 投屏区域是第一视觉焦点，使用完整宽度的深色屏幕舞台。
- 屏幕工具栏固定在舞台顶部，快捷提示收敛到底部辅助条。
- 设备操作、输入文字、剪贴板、截图、安装 APK 统一进入一个“动作带”。
- 自动化、AI、键盘映射、录制、网络、终端不再同时展开堆叠：每个能力成为可折叠的 `detail-module`，默认只展开当前正在使用的模块。
- Shell 输出使用独立的内部滚动区，输入栏固定在输出区上方，避免页面高度被命令输出撑开。

### 文件 Tab

- 路径输入和文件动作位于同一条工作区工具栏。
- 面包屑和常用路径独立成第二条导航带。
- 文件表格占据剩余空间，表格区域内部滚动，表头 sticky。
- 文件上传、新建目录、下载、删除保持原回调和确认逻辑。
- 空状态、加载态和错误态使用同一工作区占位结构。

### 应用 Tab

- 搜索、系统应用开关、快速启动、刷新、安装 APK 进入固定工具栏。
- 应用列表使用清晰的表格行，应用图标只作为识别锚点，不做卡片。
- 收藏、启动、停止、详情和更多动作保留原行为；低频动作收进更多菜单。
- 应用详情输出放入列表下方的可收起模块，默认不占用列表空间。

### 日志 Tab

- 日志筛选、级别、关键字和刷新放在顶部工具栏。
- 日志正文使用单一深色/浅色终端区域，内部滚动，支持 sticky 工具栏。
- 自动刷新、复制、清空等动作保持现有逻辑，但视觉权重低于筛选和查看。

### 设置 Tab

- 显示、输入、投屏、网络和高级设置按纵向模块分组。
- 每个模块只有一个标题带，字段使用两列信息网格；窄屏自动变单列。
- 应用、保存、重置等动作固定在对应模块末尾，避免所有按钮挤在页面顶部。
- 所有设置项继续使用现有状态和服务调用，不改变默认值或持久化键。

## 响应式与滚动

- 大于 900px：详情页使用完整宽度的纵向工作区；控制 Tab 仅允许“屏幕舞台 + 下方动作带”这一种主结构。
- 600～900px：工具栏自动换行，字段网格收为单列，详情 Tab 横向可滚动但不出现页面横向滚动。
- 小于 600px：按钮文字按现有 `Button` 能力收缩，低频动作进入更多菜单；每个数据区仍保持可读的内部滚动。
- `.detail-scroll-region`、`.table-wrap`、`.shell-output`、文件列表和应用列表设置明确 `min-height: 0` 与 `overflow: auto`。
- 页面根节点不因单个长日志、路径或命令输出产生横向溢出。
- 遵守 `prefers-reduced-motion`，只保留必要的加载反馈。

## 逻辑不变约束

以下行为必须保持：

- Tab 路由和当前设备标识不变。
- 连接、启动容器、停止、重启、投屏、ADB、文件、应用、日志、显示设置、Gnirehtet、自动化和 AI 回调不改语义。
- 现有国际化 key 和中文/英文切换继续有效；新增文案必须同时补齐中英文。
- 现有 session/local storage 键不改名。
- 离线设备仍能查看概览，受限 Tab 仍显示原因并保持原禁用行为。

## 实现范围

第一阶段集中修改：

- `src/styles/global.css`：全局令牌、模块、按钮、Tab、滚动边界和详情工作区样式。
- `src/pages/DeviceDetail.tsx`：只调整详情页壳层、Tab 导航和各工作区包装结构。
- `src/components/device/*.tsx`：仅在需要稳定模块边界或滚动边界时补充 className，不改动作逻辑。
- `src/components/layout/AppLayout.tsx`、`src/components/layout/Sidebar.tsx`：对齐全局壳层的间距和导航层级。
- `src/i18n/pages/devices.ts` 及相关页面文案：补齐新的工作区标题和辅助说明。
- `tests/`：增加结构回归测试，验证详情 Tab、滚动区域、模块边界存在，且旧的堆叠壳层未重新出现。

## 验证标准

- TypeScript 编译和生产构建成功。
- 全部现有测试通过。
- 详情页六个 Tab 均能渲染，切换后原功能回调仍可触发。
- 在线、离线、加载、空状态、错误状态均有明确布局。
- 设备列表、详情页、设置页、Docker、ADB、APK、日志和数据卷页面共享同一套间距、标题带和按钮层级。
- 在窄窗口下无页面横向溢出；文件、应用、日志、Shell 等长内容只在所属区域内部滚动。
- 视觉检查重点：没有重复入口、没有失控的大滚动条、没有无意义的卡片堆叠、没有控件全部挤到右侧。
