# 文件传输进度与取消设计规格

## 目标

在不改变现有文件上传、下载命令和既有调用方行为的前提下，为设备详情页文件传输增加可追踪状态、取消操作和尽可能准确的真实进度反馈。

## 现状与约束

- 现有 `upload_file` 和 `download_file` 命令必须继续保留，参数、返回值和成功/失败语义不变。
- 现有命令最终调用 `adb push/pull`，通用进程函数只在进程结束后返回 `ShellResult`，不能安全地在原调用上补取消信号。
- ADB 版本或运行环境可能不输出可解析的传输百分比，因此界面不得用时间或假定速度推算百分比。
- 文件页当前限制同一详情页内的并发文件传输；本设计保留该行为。
- APK 安装、文件新建、删除和其他设备操作不纳入本次传输协议改造。

## 兼容式方案

新增独立的跟踪接口，旧接口完全不动：

| 层 | 新接口 | 作用 |
| --- | --- | --- |
| 前端服务 | `uploadFileTracked(serial, local, remote, operationId)` | 启动可跟踪上传，返回既有 `ShellResult` |
| 前端服务 | `downloadFileTracked(serial, remote, local, operationId)` | 启动可跟踪下载，返回既有 `ShellResult` |
| 前端服务 | `cancelFileTransfer(operationId)` | 请求取消指定传输，返回是否找到活动传输 |
| Tauri 命令 | `upload_file_tracked` | 上传并发送进度事件 |
| Tauri 命令 | `download_file_tracked` | 下载并发送进度事件 |
| Tauri 命令 | `cancel_file_transfer` | 设置指定传输的取消标记 |

文件页只在跟踪接口和事件监听链路接入后改用新接口；项目其他调用方继续使用旧接口。

## 事件协议

事件名称固定为 `file-transfer-progress`。Rust 使用 camelCase 序列化以下载荷：

```ts
type FileTransferProgress = {
  operationId: string;
  direction: "upload" | "download";
  status: "queued" | "running" | "completed" | "failed" | "cancelled";
  bytesTransferred: number | null;
  totalBytes: number | null;
  percent: number | null;
  message: string;
};
```

事件状态必须满足：

- 一个操作最多发送一次 `queued`、一次 `running` 和一次终态事件。
- 终态只能是 `completed`、`failed` 或 `cancelled`，且终态之后不再发送同一操作的事件。
- `completed` 只表示传输和最终文件落位都成功。
- 取消标记被观察到并终止进程后发送 `cancelled`；用户点击取消本身不提前伪造终态。
- 无法取得真实字节进度时，`bytesTransferred`、`totalBytes`、`percent` 使用 `null`，界面显示不确定进度。
- 如果 ADB 输出提供可解析百分比，后端只发送单调不减且限制在 `0..100` 的真实映射值；不进行时间估算。

## Rust 后端边界

### 传输注册表

新增聚焦于传输生命周期的服务模块，例如 `src-tauri/src/services/transfer.rs`，提供受 Tauri managed state 管理的 `TransferRegistry`：

- `start(operation_id) -> Result<Arc<AtomicBool>, String>`：拒绝空 ID和重复活动 ID。
- `cancel(operation_id) -> bool`：只设置对应操作的取消标记，不直接触碰其他进程。
- `finish(operation_id)`：无论成功、失败或取消都移除注册表项。
- 注册表只保存取消标记，不保存前端路径或敏感文件内容。

### 可取消进程

在 `src-tauri/src/services/util.rs` 增加独立的可取消命令执行路径，不修改现有 `run_command_timeout`：

- 子进程必须使用管道读取 stdout/stderr，避免输出过多导致阻塞。
- 运行期间周期性检查取消标记和超时；取消时按现有平台策略终止进程树。
- 返回结果必须能区分正常失败、超时和用户取消，供传输层选择 `failed` 或 `cancelled`。
- 仍使用现有 ADB 路径和 120 秒超时，避免改变工具解析和配置行为。

### 上传安全落位

跟踪上传使用当前远程路径旁的唯一临时路径：

1. 先将本地文件推送到远程临时路径。
2. 只有推送成功且未取消时，才通过设备端 `mv -f` 落位到目标路径。
3. 失败或取消时尽力删除远程临时路径，不删除原目标文件。

这样取消时不会把半截文件暴露为用户选择的目标文件。跟踪接口仅服务于文件页当前的单文件上传场景；旧接口继续保留原有 ADB 行为。

### 下载安全落位

跟踪下载沿用现有“先下载到目标目录临时目录，再移动到用户选择路径”的策略：

- 成功前不覆盖用户选择的最终文件。
- 失败或取消时清理临时目录；清理失败只记录日志，不覆盖主要传输错误。
- 目录目标继续保持现有 `adb pull` 语义。

### 进度来源

- 上传总大小来自本地文件元数据。
- 下载总大小优先来自可读取的远程文件大小；不可读取时为 `null`。
- 已传输字节/百分比优先解析 ADB 的实时进度输出。
- 解析器必须容忍回车刷新、空白和无进度输出；解析失败不影响传输本身，只会退化为不确定进度。

## 前端行为

文件页启动传输前先注册事件监听，再调用跟踪接口，确保不丢失 `queued` 事件。监听器只接受匹配当前 `operationId` 的事件，并在组件卸载或终态后清理。

界面规则：

- 运行中显示方向、文件名和不确定进度；有 `percent` 时显示百分比和进度条。
- 运行中显示“取消”按钮，点击后只发出一次取消请求，并把文案切换为“正在取消”。
- 取消、失败和成功都恢复上传/下载按钮可用状态。
- 取消不弹错误告警；真正失败保留现有错误反馈和重试入口。
- 重试生成新的 `operationId`，复用已有本地/远程路径，不重新打开文件选择器或保存对话框。
- 旧的错误反馈、重复点击保护和文件列表刷新行为必须继续保留。

若跟踪命令或事件监听不可用，传输结果仍以命令返回值为准；不显示虚假的百分比，也不破坏现有错误处理。

## 测试验收标准

### Rust

- 事件载荷 camelCase 序列化字段与前端类型一致。
- 注册表覆盖空 ID、重复 ID、取消存在操作、取消不存在操作和完成清理。
- ADB 进度解析覆盖正常百分比、回车刷新、边界值、异常文本和无进度输出。
- 可取消命令在取消标记触发后返回“已取消”结果，并且正常成功、非零退出和超时仍能区分。
- 上传/下载临时落位路径在成功、失败和取消分支都覆盖清理与不覆盖最终文件的约束。

### 前端

- 事件只更新匹配的传输，不会串到其他操作。
- 有百分比时显示百分比，无百分比时显示不确定进度。
- 取消按钮只调用一次取消命令，收到取消终态后恢复交互且不触发错误告警。
- 失败仍显示重试；重试不重新打开 picker/save 对话框，并使用新的操作 ID。
- 组件卸载会解除事件监听，迟到事件不会更新已卸载页面。
- 现有文件操作错误、重复上传保护、成功后的列表刷新回归测试全部继续通过。

## 非目标

- 不修改现有 `upload_file` / `download_file` 的协议或实现路径。
- 不添加断点续传、传输队列、后台持久化任务或跨应用恢复。
- 不对无法从 ADB 得到的进度进行估算。
- 不扩展到 APK 安装和其他长时设备操作。
