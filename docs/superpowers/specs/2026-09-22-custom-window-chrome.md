# 主窗口自定义标题栏设计

## 目标

移除主窗口顶部的 Windows 原生标题栏，把最小化、最大化/还原、关闭按钮放入现有应用顶部导航栏的最右侧，减少一层重复的顶部空间。

## 范围

- 主窗口的 Tauri 配置改为无原生装饰。
- 现有 `Sidebar` 顶部导航栏增加独立的窗口控制区。
- 窗口控制区调用 Tauri Window API：最小化、最大化/还原、关闭。
- 最大化状态变化时同步按钮图标和无障碍标签。
- 顶部导航栏的空白区域作为窗口拖动区域；导航、设置和窗口按钮不参与拖动。
- 保留现有 `closeToTray` 的关闭拦截行为。
- 独立终端窗口不在本次范围内，继续使用系统标题栏。

## 交互与布局

```text
[ Just Run / Device tools ] [可拖动空白区] [导航] [设置] | [最小化] [最大化/还原] [关闭]
```

- 控制按钮固定在当前顶部导航最右侧，不放进可横向滚动的导航列表。
- 关闭按钮悬停时使用危险色背景；另外两个按钮使用普通悬停态。
- 每个按钮提供 `aria-label` 和 `title`。
- 窗口宽度较小时，导航可滚动或换行，但窗口控制区保持可见。

## 验收标准

1. 主窗口不再显示系统标题栏，但仍可从顶部空白区域拖动。
2. 三个按钮分别执行最小化、最大化/还原和关闭；最大化后按钮变为还原语义。
3. 点击导航、设置和窗口按钮不会触发窗口拖动。
4. 开启关闭到托盘时，点击关闭仍沿用现有隐藏行为。
5. 前端类型检查、相关 Vitest 和项目既有四套验证命令通过。
6. 最小化、最大化、关闭、拖动、窗口贴边和 DPI 行为需在真实 Tauri 窗口中人工确认，不以 DOM 测试代替。

## 交互链路修复

上一版只声明了 `data-tauri-drag-region`，没有显式调用原生拖动 API，也没有无边框窗口的边缘缩放命中区。修复版采用以下链路：

- 顶部拖动区左键按下调用 `startDragging()`；双击调用 `toggleMaximize()`。
- 窗口四边和四角各放置一个透明命中区，分别调用 `startResizeDragging(direction)`。
- 缩放使用 Tauri 原生窗口 API，由系统处理最小尺寸、贴边和 DPI 换算；前端不自行换算物理像素。
- 最大化状态继续通过 `onResized` 和 `onScaleChanged` 同步，避免跨显示器或 DPI 切换后按钮语义过期。

## Tauri 权限

主窗口 capability 必须显式允许自定义标题栏使用的五个窗口命令：关闭、最小化、切换最大化、开始拖动和开始边缘缩放。`core:window:default` 不包含这五项时，前端调用会被 ACL 拒绝。

## 桌面图标

任务栏、窗口和托盘图标统一使用 `public/just-run-logo.png` 生成的 Tauri 桌面图标资源，Windows 重点更新 `src-tauri/icons/icon.ico`，同时保持配置中引用的 PNG、ICNS 和 Appx 尺寸一致。
