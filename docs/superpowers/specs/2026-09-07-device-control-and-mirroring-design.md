# 设备操作与投屏体验优化设计

日期：2026-09-07  
范围：Redroid Device Center 第一轮体验优化  
状态：已确认，待实施

## 1. 目标

在不破坏现有设备管理、ADB、截图和独立 scrcpy 功能的前提下，提升设备详情页的控制可靠性和投屏操作体验：

- 每个控制动作都有明确的进行中、成功或失败反馈。
- 失败时保留后端真实原因，并保证按钮不会永久停留在忙碌或禁用状态。
- 截图预览有清晰的生命周期、手动刷新、自动刷新、错误重试和最近更新时间。
- scrcpy 的启动、停止、重连和异常退出状态更容易理解和恢复。
- 常用设备操作更集中、更容易发现，同时保留现有鼠标手势和入口。
- Shell 执行失败可见、可重试，历史和收藏行为保持兼容。

## 2. 非目标与兼容边界

本轮明确不做以下变更：

- 不把 scrcpy 视频流嵌入 WebView，不引入新的视频编解码或窗口注入链路。
- 不删除现有独立 scrcpy 窗口、截图预览、鼠标点击/拖动/滚轮/右键/中键操作。
- 不修改 Rust 命令名称、命令参数和已有设置字段的含义。
- 不改变设备、容器、数据卷和自动启动的数据模型。
- 不默认增加高频截图请求；预览只有在用户开启或已有预览时才刷新，后台页面和离线设备暂停刷新。

## 3. 当前实现与问题边界

设备详情页当前把概览、控制、文件、应用、Logcat、设置和 Root 逻辑集中在一个较大的页面文件中。控制区同时承担截图预览、鼠标手势、scrcpy 生命周期、按键、文本输入、剪贴板和 ADB Shell。

本轮重点处理以下已确认的行为问题：

1. 部分控制调用只等待 Promise 完成，没有统一检查 `ShellResult.success`，后端返回失败时界面仍可能恢复为“就绪”。
2. Shell 请求没有统一的异常恢复路径，调用失败时输出区和状态栏可能缺少可操作的错误信息。
3. scrcpy 状态依赖轮询，启动、停止和重连的忙碌状态不统一，进程异常退出时缺少明确的重试入口。
4. 截图预览的“实时画面”文案容易让人误认为是低延迟视频；预览刷新失败时没有独立的错误态和重试动作。
5. 常用按键和更多按键混在同一个区域，旋转操作只有单向参数，输入空内容也可以提交。

## 4. 方案与结构

采用渐进式增强方案，继续以现有 `DeviceService` 和 Rust 命令为唯一设备操作入口。新增的前端抽象只负责统一状态和反馈，不绕过服务层。

### 4.1 操作执行器

新增一个可测试的前端操作执行辅助模块，负责：

- 设置当前动作标签和忙碌状态。
- 调用返回 `ShellResult` 的服务方法。
- 当 `success === false` 时抛出带有 `stderr`、`stdout` 或默认文案的错误。
- 成功后触发调用方提供的刷新动作。
- 无论成功还是失败，都在 `finally` 中恢复控件可用状态。

执行器不持有全局设备状态，忙碌状态留在设备详情控制区，避免影响设备列表和其它页面。不同动作使用稳定的 key，防止连续点击同一动作；不相关的只读操作仍可按现有行为执行。

### 4.2 截图预览

把现有截图区域整理成明确的预览状态：

- `empty`：尚未请求截图，显示“刷新截图”入口和独立 scrcpy 说明。
- `loading`：正在获取截图，显示轻量加载状态并禁用重复刷新。
- `ready`：显示截图、更新时间、手动刷新和自动刷新开关。
- `error`：保留上一张成功截图（如果存在），在工具条显示错误原因和“重试”。

刷新策略：

- 不主动对没有打开预览的设备进行截图轮询。
- 开启自动刷新后使用固定的低频间隔，避免影响 ADB；页面隐藏或设备离线时暂停。
- 每次 ADB 点击、滑动、按键或截图成功后，只触发一次受控刷新，不叠加定时器。
- 预览的图片坐标仍按设备分辨率映射，保留现有鼠标操作语义。
- 文案改为“截图预览/自动刷新”，不宣称为 scrcpy 视频流。

### 4.3 scrcpy 生命周期

继续使用现有 `scrcpyStart`、`scrcpyStop`、`scrcpyRestart` 和 `scrcpyStatus`：

- 启动前保留现有 TCP ADB 连接检查。
- 启动、停止、重连分别有独立忙碌状态，操作期间防止重复提交。
- 返回失败时显示 stderr/stdout，并把可诊断信息追加到 Shell 输出区。
- 启动成功后立即刷新一次状态，再继续低频轮询。
- 轮询发现进程退出时显示“已停止/异常退出”，提供重试，不自动修改设备或容器状态。
- 现有设备设置中的 scrcpy 参数继续作为启动参数来源；不改变当前参数过滤规则。

### 4.4 控制面板

保留所有现有动作，并按使用频率重新分组：

- 导航：HOME、BACK、RECENT。
- 设备状态：亮屏、锁屏、电源、音量、通知栏、设置。
- 显示：截图、刷新预览、旋转方向切换、全屏。
- 输入：文本输入和剪贴板发送；空内容提交前给出提示。

现有鼠标手势继续保留，并让画面区获得焦点后支持有限的键盘快捷操作。快捷键只在画面区聚焦且当前焦点不是输入框/选择框时生效，避免影响 Shell、文本输入和页面导航。

### 4.5 ADB Shell

- 增加执行中状态，执行期间禁用重复提交。
- 统一捕获服务异常和 `ShellResult.success === false`。
- 输出同时保留 stdout、stderr 和退出码，失败状态明确可见。
- 保留现有历史、收藏及 session/localStorage 存储格式。
- 清空输出只清理当前输出，不清理命令历史；保持现有用户预期。

## 5. 文件边界

优先把可独立测试的逻辑放到小模块，避免继续扩大 `DeviceDetail.tsx`：

- `src/lib/deviceActions.ts`：设备动作结果判定和统一执行辅助逻辑。
- `src/components/device/DevicePreview.tsx`：截图预览状态、刷新计时和画面区交互。
- `src/components/device/DeviceControlPanel.tsx`：常用按键、输入、截图和 scrcpy 工具条。
- `src/components/device/DeviceShell.tsx`：Shell 输入、输出、收藏和历史。
- `src/pages/DeviceDetail.tsx`：负责设备数据、Tab 组织和组件间参数传递。
- `src/i18n/pages/deviceDetail.ts`：新增中英文文案，保持中文词典为源语言。
- `src/styles/global.css`：只增加预览/控制区需要的样式，不重置已有布局规则。

如果拆分过程发现现有子组件边界不适合直接迁移，则先在原文件内完成行为修复，再进行保持行为不变的局部提取；不为拆分而拆分。

## 6. 错误处理

- 服务层抛出的异常统一进入状态栏或操作区错误反馈，不使用静默 catch。
- `ShellResult.success === false` 一律视为失败，即使 Promise 正常返回。
- 错误显示优先级为 `stderr` → `stdout` → 页面对应的本地化默认文案。
- 截图失败不清空上一张成功截图；用户可以直接重试。
- scrcpy 失败不改变设备在线状态；只更新 scrcpy 状态和诊断输出。
- 设备离线时沿用现有禁用规则，并在用户尝试操作时给出“设备未在线”反馈。
- 所有计时器、事件监听和轮询在组件卸载或 serial 变化时清理。

## 7. 测试与验收

本轮增加前端单元测试，并以现有 TypeScript 构建作为回归检查。重点测试：

- `ShellResult.success === false` 会变成失败而不是成功。
- 服务抛异常后动作状态会恢复，错误信息可被读取。
- 截图失败进入错误态且保留上一张成功预览。
- 自动刷新在页面隐藏/设备离线时暂停，恢复后不会创建重复计时器。
- 空文本和空剪贴板不会调用服务。
- scrcpy 启动失败会保留诊断信息并允许再次启动。

验收标准：

1. 现有设备列表、设备详情、ADB、Docker、APK、文件和 Logcat 入口不改变。
2. 原有鼠标控制和独立 scrcpy 窗口仍可用。
3. 任意控制动作失败后，按钮在本次操作结束后可再次点击。
4. 截图预览的成功、失败、重试、暂停和恢复状态都可见。
5. 中文和英文界面均有对应文案，构建无 TypeScript 错误。
6. 新增测试全部通过，且 `npm run build` 通过。

## 8. 实施顺序

按以下顺序实施，每一步都先写失败测试，再写最小实现并运行回归：

1. 建立测试运行入口，覆盖动作结果判定和状态恢复。
2. 修复并统一控制动作、Shell、截图的失败反馈。
3. 提取截图预览并补齐手动刷新、自动刷新和错误重试。
4. 优化 scrcpy 生命周期反馈与控制工具条。
5. 整理控制面板、输入校验和有限键盘快捷键。
6. 补齐双语文案、样式和页面级回归检查。
