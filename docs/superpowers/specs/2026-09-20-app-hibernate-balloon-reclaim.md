# 应用暂停后的 guest 内存回收设计

## 目标

用户点击“暂停应用”并成功执行 Android `force-stop` 后，继续尝试一次由
qemu-center 负责计算和验证的 virtio-balloon 回收，让 guest 已释放的页面有机会
返回给 QEMU/宿主机。

## 约束

- 只在应用暂停成功后尝试；应用包名、设备映射、闲置策略或 ADB 停止失败时不触发。
- 不改变 QEMU 的下一次启动内存上限，不改 qcow2，不停止容器或 VM。
- qemu-center 继续负责实例状态、cgroup 指标、保留量、目标值和 QMP `actual` 校验；
  Tauri 只发起已有的安全命令。
- balloon 失败不回滚已经成功的应用暂停，也不把“应用已暂停”报告成失败。
- 结果 reason 记录为 `idle_app_reclaimed` 或保留 `idle_app`，供日志/诊断区分；
  UI 仍显示应用暂停成功。

## 验收

1. 成功暂停应用时会调用一次 guest 回收策略。
2. 应用暂停失败、映射不匹配或前置校验失败时不会调用回收。
3. 回收失败时仍返回成功的应用暂停结果。
4. 原有四套测试门禁保持通过。
5. 真实 WHPX 下的宿主工作集变化仍必须人工测量，自动化测试不得宣称固定节省量。
