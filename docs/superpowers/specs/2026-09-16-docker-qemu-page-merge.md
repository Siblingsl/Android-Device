# 容器与节点页合并方案（页面合并 / 功能不合并）

> 状态：已定稿（开放问题全部收敛，见第 10 节）
> 日期：2026-09-16
> 范围：前端信息架构与生命周期治理。不改后端命令语义、不改 qemu-center CLI、不改持久化格式。
> 决策来源：与仓库主人的逐项确认（第 10 节列出「问题 / 决策 / 影响」）。

## 1. 结论

推荐「单页双轨」：新增合并页（路由 `/containers`，侧边栏入口名「容器与节点」），把 `src/pages/Docker.tsx` 与 `src/pages/QemuCenter.tsx` 的页面主体**原样搬运**成两个轨道面板；外壳只负责页头、轨道切换、深链与生命周期治理。

达成"页面合并"（一个入口、一套页头、一处切换），同时严格保证"功能不合并"（两条轨道的请求类型、服务调用面、后端语义、可用性提示全部不变）。

判据不是新发明的，而是沿用仓库既有先例：`src-tauri/src/services/unified.rs` 已在数据层把两条轨道的设备流合成为一条，并用零耦合规则保证两轨互不侵入。**合并的是入口与呈现，不合并的是能力与语义。**

## 2. 现状（只读实测）

| 项 | Docker 轨道 | QEMU 轨道 |
| --- | --- | --- |
| 路由 | `/docker` → `DockerPage` | `/qemu` → `QemuCenterPage` |
| 侧边栏 | `{ to:"/docker", icon:Container, key:"common.nav.docker" }` | `{ to:"/qemu", icon:Server, key:"common.nav.qemu" }` |
| 页面文件 | `src/pages/Docker.tsx`（2195 行） | `src/pages/QemuCenter.tsx`（1411 行） |
| i18n | `src/i18n/pages/docker.ts`（485 行，`docker.*` 引用 259 处） | `src/i18n/pages/qemu.ts`（365 行，含 `common.nav.qemu`） |
| 服务出口 | `DeviceService`（`docker_*`） | `DeviceService` + `QemuService`（`qemu_*`） |
| 创建请求类型 | `CreateInstanceRequest` | `QemuRedroidCreateRequest`（含预装/伪装扩展字段） |

合并真正要处理的耦合点（实测定位）：

| 耦合点 | 位置 | 为什么是问题 |
| --- | --- | --- |
| 各自独立轮询 | `Docker.tsx:183`、`QemuCenter.tsx:338` 的 `setInterval` | 两面板同时挂载会变双份轮询 |
| 共享全局状态行 | `appStore.statusText`（两页都写） | 合并后会互相覆写 |
| QEMU 长任务全局态 | `appStore.qemuSetup{running,step,startedAt,refreshing}`、`qemuWaitVm`（注释原文：VM whose guest-SSH wait was interrupted by a page switch） | 仓库已处理过"切页打断长任务"，合并不得让其退化 |
| 共享 UI 基元 | `Card/Button/Skeleton`、`askConfirm`、`copyText`、`createRequestSequence`、`useI18n` | 说明公共外壳成本低、风格已统一 |
| 显示规格预设 | `lib/displaySpec.ts` | 已属公共资产，无需合并 |

## 3. 目标与非目标

目标：

- 侧边栏两个入口收敛为**一个**「容器与节点」入口，进入后在同一页面内切换轨道。
- 统一页头与切轨控件；两轨内容区各自保持现有视觉骨架。
- 提供可分享深链（含轨道与选中对象）；旧路由不失效。
- 治理生命周期：非活跃轨道不轮询；跨轨切换不丢进行中的长任务。

非目标（"功能不合并"的具体含义，须写入验收断言）：

- 不合并创建请求类型：`CreateInstanceRequest` 与 `QemuRedroidCreateRequest` 保持独立字段集。
- 不合并服务调用面：Docker 轨道继续走 `docker_*`，QEMU 轨道继续走 `qemu_*`；不新增"统一创建"命令。
- 不把两条轨道的实例列表合并成一张可混操作的表格。
- 不做跨轨道迁移/平移实例。
- 不合并两条轨道的日志面板（已决策：各自独立；内容与格式不同，强行合并会篡改语义）。
- 不统一两轨的错误语义与可用性提示（QEMU 为实验性轨道且依赖 CLI/WHPX；Docker 依赖 Docker Desktop/WSL 内核，差异必须继续如实呈现）。
- 不让「跨轨对比视图」演变为跨轨操作：它必须是**只读聚合**。
- 不合并后端/CLI：`qemu-center` 与 `src-tauri` 的行为、参数、持久化格式一律不动。

允许的公共化：抽出纯外壳（页头、切轨控件、轨道容器、来源徽标）；只抽两轨行为完全一致的展示型小组件；共享只读工具（`lib/displaySpec.ts`、`askConfirm`、`copyText`、i18n）。

## 4. 已有先例：unified.rs 的零耦合规约

| unified.rs（数据层） | 页面合并的对应做法 |
| --- | --- |
| 两轨只在唯一聚合模块相遇，互不 import | 两轨面板组件互不 import；只在外壳里被引用 |
| QEMU 实例以 `serde flatten` 打标，不改造原结构 | 轨道面板以 `active` 等 props 打标，不改造面板内部状态模型 |
| 两轨经同一条 adb 通道到达设备，`id` 即 serial | 合并页只做供给/节点管理；设备操作仍归 Device Center |
| 诚实状态分层（单测覆盖 vs 需真机实测） | 验收标准区分「可自动断言」与「需真机确认」 |

## 5. 候选方案

| 方案 | 做法 | 页面合并 | 功能隔离 | 改动量 | 主要风险 | 评分 |
| --- | --- | --- | --- | --- | --- | --- |
| A 单页双轨（选定） | 一个路由 + 轨道分段控件；两轨面板原样搬运；外壳管生命周期 | 强 | 强 | 中 | 挂载与轮询治理、状态行来源化 | 9/10 |
| B 单列表双来源 | 一张实例总表，行内标来源 | 强 | 弱 | 大 | 语义混合、操作集分叉 | 4/10 |
| C 只合并导航 | 一个入口 + 页内二级导航，仍两页 | 中 | 强 | 小 | 视觉仍是两页 | 6/10 |
| D 只抽公共组件 | 两页保持，抽重复组件 | 无 | 强 | 小 | 未真正合并页面 | 3/10 |

实施路径：A 为主体；C 作为 A 的第一阶段（风险最低，可随时停在可用状态）。B 与"功能不合并"正面冲突，仅作反例。

## 6. 详设

### 6.1 路由与深链

| 路由 | 语义 | 处理 |
| --- | --- | --- |
| `/containers` | 合并页（新主入口） | 新增；默认轨道 = 记忆上次选择。解析优先级：URL `?track=` > 上次选择（持久化） > 首次兜底「本机 Docker」 |
| `/containers?track=docker` / `?track=qemu` | 指定轨道 | 分段控件的选择写入 URL |
| `/containers?track=qemu&vm=node1&inst=r13` | 轨道内选中对象 | 刷新/分享可还原 |
| `/docker`、`/qemu` | 旧深链 / 书签 | 保留并重定向到对应轨道（已决策）；**不在侧边栏保留二级项**——合并的诉求就是单一入口；永久保留重定向 |

### 6.2 页面骨架

```
┌──────────────────────────────────────────────────────────────┐
│ 页头（外壳）：标题「容器与节点」 + 来源徽标（数量 + 健康度）      │
├──────────────────────────────────────────────────────────────┤
│ 轨道分段控件（tablist）：[ 本机 Docker ] [ QEMU 节点 ]  [?track=]│
├──────────────────────────────────────────────────────────────┤
│ 面板容器（外壳只管挂载/暂停，不介入内部）                        │
│   DockerTrackPanel（原 Docker.tsx 主体） / QemuTrackPanel       │
├──────────────────────────────────────────────────────────────┤
│ 后台任务常驻条（有进行中长任务且不在该轨道时出现）[ 回到该轨道 ]  │
└──────────────────────────────────────────────────────────────┘
```

### 6.3 组件拆分（只搬不改）

| 产物 | 来源 | 约束 |
| --- | --- | --- |
| `RuntimePage`（外壳） | 新增 | 只持轨道选择、深链同步、挂载策略、常驻条；不直接调用 `docker_*`/`qemu_*` |
| `DockerTrackPanel` | `Docker.tsx` 主体 | 内部状态、服务调用、i18n 键、CSS 类名一律不变 |
| `QemuTrackPanel` | `QemuCenter.tsx` 主体 | 同上；保留实验性提示与 CLI 缺失提示 |
| 轨道切换控件 | 外壳内新增 | tablist/tab/tabpanel 语义，键盘可切换 |
| 来源统计徽标 | 外壳内新增 | 只读；数据来自既有只读命令 |

### 6.4 生命周期与轮询治理（合并的真正难点）

| 情形 | 策略 | 理由 |
| --- | --- | --- |
| 默认（无长任务） | 只挂载活跃轨道，非活跃轨道不渲染不轮询 | 零双份轮询（两轨各有 interval） |
| 有长任务时切轨 | 该轨道保持挂载但隐藏，并显示常驻条 | 复用既有 `qemuSetup.running` / `qemuWaitVm` / Docker 的 `creatingTask`，禁止清空进行中状态 |
| 隐藏期间轮询 | 降频或暂停业务轮询，只保留任务进度所需刷新 | 避免双份轮询 |
| 状态行 | 各轨渲染自己的状态行；若必须共用 `appStore.statusText`，写入时带来源标签 | 现状两页写同一字段会互相覆写 |
| 日志面板 | 各自独立（已决策） | 内容与格式不同 |

### 6.5 与 Device Center 的边界

| 能力 | 归属 |
| --- | --- |
| 供给、节点管理、预装、验收 | 合并页（本方案） |
| 设备操作（投屏/文件/应用/Shell/控制/伪装） | Device Center（`/devices`），数据源已由 `unified.rs` 统一 |
| 反向入口 | 建议从设备详情跳回合并页对应轨道（按 serial 定位实例） |

### 6.6 i18n

- 保留 `docker.*` 与 `qemu.*` 命名空间，不迁移旧键（迁移只增加回归面）。
- 新增外壳键（已定文案）：`common.nav.containers` = 「容器与节点」/ `Containers & Nodes`；另有 `runtime.title`、`runtime.subtitle`、`runtime.track.docker`（本机 Docker）、`runtime.track.qemu`（QEMU 节点）、`runtime.backgroundTask.*`、`runtime.compare.*` 等。
- 旧键 `common.nav.docker` / `common.nav.qemu` 至少保留一个版本（供旧路由落地与测试）。

### 6.7 视觉与无障碍

- 外壳复用现有 `Card` 与留白节奏；不重排两轨内部布局，把视觉回归面压到最小。
- 切轨控件用 tablist 语义并支持键盘；切轨后焦点落在新的 tabpanel 顶部。
- 实验性轨道标识（QEMU）继续留在面板内，不在外壳层统一标注，避免抹平差异。

### 6.8 健康度徽标与跨轨对比视图（已决策要做）

健康度徽标口径：

- 显示数量 + 健康度，例如 `本机 Docker · 3 容器 · 正常`、`QEMU · 1 节点 / 2 实例 · 体检 8/8（12 分钟前）`。
- **不得每次进页现场体检**：QEMU 的 WHPX 探针为秒级开销且含超时项；徽标一律读缓存的体检结果，标注「上次检查 N 分钟前」，提供显式刷新。
- Docker 侧取现有 Docker/WSL 内核状态（复用既有只读检测）。
- 不可用时必须写清原因（Docker 未启动 / CLI 缺失 / 节点停机），不得只显示 0。

跨轨对比视图（只读聚合，新增能力）：

| 维度 | 设计 |
| --- | --- |
| 定位 | 只读聚合视图，无任何写操作，不构成"功能合并"；放在合并页二级入口 |
| 分组维度 | Android 版本（两轨唯一可对齐的公共维度）；未对齐版本独立列出并标注"单轨独有" |
| 指标 | 实例数 / 运行中 / CPU 配额与实际占用 / 内存配额与实际 / 磁盘占用 / 启动耗时 / 健康度摘要 |
| 数据来源 | Docker 轨道：既有只读命令；QEMU 轨道：经 SSH 在 guest 内执行只读 docker 命令，并复用 doctor/verify 已有输出 |
| 采集成本 | 按需采集（进入一次 + 手动刷新），不进入常驻轮询 |
| 不可用语义 | 节点停机/CLI 缺失时显示"不可用（原因）"，不得显示 0 |
| 呈现 | 表格 + 轻量条形（用元素宽度表达比例），不引入图表库与远程资源 |

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 非活跃轨道仍在轮询 | 资源浪费、状态抖动 | `active` props 契约 + fake timers 断言 |
| 切轨打断长任务 | 用户重复提交 | 保持挂载 + 常驻条 + 复用既有任务标记 |
| 状态行互相覆写 | 提示错乱 | 状态来源化 |

| 视觉回归面过大 | 测试大面积调整 | 面板内部布局与 CSS 命名空间不动 |
| 对比视图越界成写操作 | 破坏"功能不合并" | 只读调用面白名单断言 |

## 9. 验收标准

可自动断言：

1. 两个轨道面板互不 import（依赖方向单向）。
2. Docker 轨道仅调用 `docker_*` 命令集；QEMU 轨道仅调用 `qemu_*` + 既有公共命令（服务 mock 调用面断言）。
3. 切轨后非活跃轨道零轮询（fake timers + spy 计数为 0）。
4. 切轨不丢进行中任务（`qemuSetup.running` / `creatingTask` 保持 + 常驻条出现）。
5. 旧路由 `/docker`、`/qemu` 正确落到对应轨道。
6. 深链 `?track=&vm=&inst=` 还原选中态。
7. 现有测试全绿 + 类型检查 0 错误。
8. 侧边栏只剩一个入口；旧路由仍可用。
9. 健康度徽标不触发现场体检（进入页面后 doctor 调用计数为 0，仅显式刷新时 > 0）。
10. 跨轨对比视图无写操作（只读调用面白名单断言）。
11. 对比视图按需采集，不进入常驻轮询。

需人工确认（真机）：

- Docker 轨道：创建实例全流程、取消创建清理、内核切换/恢复（含 `wsl --shutdown` 提示）、实例筛选。
- QEMU 轨道：节点启停、体检八项、实例创建（含预装）、升级预装、恢复升级前、验收七项、日志与状态行。
- 跨轨切换：QEMU 长任务进行中切到 Docker 轨道再切回，任务不丢、进度连续。

## 11. 边界声明

- 本方案只涉及前端信息架构与生命周期治理，不改动 `src-tauri` 命令语义、`qemu-center` CLI 行为、持久化格式与任何后端协议。
- 不削弱现有"诚实呈现"：QEMU 轨道的实验性提示、CLI 缺失提示、验收七项中 UNTESTED 与 FAIL 的区分、Docker 不可用时的显式告警，全部保留。
