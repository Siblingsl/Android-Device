# 系统级全局快捷键设计

## 背景与目标

当前项目已经有应用窗口内的快捷键配置和执行逻辑，但应用失去焦点后快捷键不会触发。本次增加 Tauri 原生系统级快捷键注册能力，让用户在其他窗口工作时也能快速回到仪表盘、设备中心、终端、设置或刷新工作区，同时保持现有设备控制快捷键和页面行为不变。

## 范围

本次包含：

- 使用 Tauri v2 `global-shortcut` 插件注册系统级快捷键。
- 设置页增加“启用系统级快捷键”开关。
- 复用现有五个安全动作：打开仪表盘、打开设备中心、打开终端、刷新工作区、打开设置。
- 继续保留应用内快捷键监听，作为 Web 预览和原生注册失败时的兜底。
- 显示每个快捷键的注册状态；单个快捷键被占用时只标记该项失败。
- 保持现有本地快捷键配置格式兼容，不修改后端 `AppSettings` 结构。

本次不包含：

- 不为关机、重启、删除、卸载、批量安装等高风险设备动作默认注册全局快捷键。
- 不修改 scrcpy、ADB、Docker、文件传输或设备控制流程。
- 不要求新增后台常驻进程；快捷键生命周期跟随客户端窗口。

## 设计方案

### 1. 配置与快捷键格式

继续使用本地存储键 `rdc.shortcuts` 保存五个动作的用户配置，并新增 `rdc.shortcuts.enabled` 保存系统级快捷键开关，默认启用。

前端显示格式保持现有 `Ctrl+Shift+P` 风格。注册到 Tauri 插件时转换为兼容格式：

- `Ctrl` 和 `Meta` 统一转换为 `CommandOrControl`。
- `Alt`、`Shift` 和普通按键保持语义不变。
- 解析失败或只有修饰键的配置不会注册。

### 2. 注册生命周期

新增独立的全局快捷键管理模块，负责：

1. 注销上一组由本应用注册的快捷键。
2. 读取当前开关和快捷键配置。
3. 按动作逐项注册，记录成功和失败结果。
4. 将触发的插件快捷键映射回现有 `ShortcutAction`。
5. 配置变更或开关切换后重新注册。
6. 页面卸载或应用退出前注销全部快捷键。

首次启动时先尝试注册；Tauri Web 预览环境没有插件时静默降级为现有应用内快捷键。注册失败不会阻止应用启动。

### 3. 动作执行

全局快捷键触发后复用 AppLayout 的统一动作分发：

- 导航动作使用现有 `navigate`。
- 刷新动作复用现有 `refreshStatus` 和 `refreshDevices`。
- 如果客户端窗口处于隐藏、最小化或后台状态，先请求显示并聚焦窗口，再执行导航；显示/聚焦失败不影响动作本身。

应用内监听与原生插件触发使用相同的动作映射，避免维护两份业务逻辑。输入框、文本域、下拉框和按钮聚焦时继续由原有控件处理，不抢占输入。

### 4. 设置页反馈

快捷键卡片增加：

- “启用系统级快捷键”开关。
- 当前注册状态摘要：已注册数量 / 总数量。
- 每一行动作的状态标记：已注册、未启用、被占用或格式无效。
- 注册错误使用现有状态栏和卡片内提示，不弹出连续阻塞式弹窗。

快捷键本地配置仍然即时保存；启用开关变化也即时保存并触发重新注册。恢复默认快捷键会同时触发一次重新注册。

## 错误处理与兼容性

- 系统已有相同快捷键时，插件返回错误；该动作显示“被占用”，其余动作继续注册。
- 原生插件不可用、权限缺失或平台不支持时，系统级状态显示不可用，但应用内快捷键继续工作。
- 读取损坏的本地快捷键数据时沿用现有默认值恢复策略。
- 新增依赖只在桌面目标启用，避免影响非桌面编译目标。
- 不把快捷键配置写入 `settings.json`，因此旧版本配置文件无需迁移。

## 测试策略

- 测试快捷键显示格式到 Tauri 注册格式的转换，包括 Ctrl/Meta、Alt、Shift、标点和无效输入。
- 测试启用/禁用时的注册与注销顺序。
- 测试单个注册失败不会阻止其余快捷键注册。
- 测试设置页开关、状态文案、恢复默认和冲突提示。
- 测试全局触发动作与应用内触发动作使用相同动作映射。
- 运行全量前端测试、TypeScript/Vite 构建和 Tauri 桌面构建。

## 验收标准

1. 应用窗口不在前台时，启用的快捷键仍能触发对应页面或刷新动作。
2. 设置页可以关闭系统级快捷键，关闭后插件不再占用这些组合键。
3. 任意一个组合键被其他程序占用时，客户端仍正常启动，其他快捷键仍可用。
4. 原有应用内快捷键、设备详情页控制键以及所有既有功能测试不回归。
5. Web 预览环境不因缺少 Tauri 插件而白屏或报错。
