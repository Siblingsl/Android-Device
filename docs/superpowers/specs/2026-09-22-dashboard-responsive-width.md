# Dashboard 响应式宽度方案

## 目标

窗口从紧凑尺寸放大到宽屏后，Dashboard 的内容容器和模块占满可用宽度，而不是停在固定的最大宽度。

## 根因

`--content-max` 同时限制了顶部栏和页面内容；上一轮改成 `1800px` 后，宽于 1800px 的窗口仍只增加两侧空白，内部网格没有更多宽度可分配。

## 方案

- 保留现有 `grid` 列、900px/600px 响应式断点和窄屏折叠行为。
- 将共享容器宽度改为 `100%`，让页面内容使用 `.content` 提供的 18px 内边距；小窗口继续由现有媒体查询负责折叠。
- 顶部栏与页面内容继续使用同一个变量，确保两者边界对齐。

## 验收

- CSS 不再给宽屏内容设置固定最大宽度。
- 共享容器在桌面端占满可用宽度，仅保留页面自身的内边距。
- 既有 Dashboard 网格对齐与窄屏断言保持通过。
- 视觉效果仍需用户在真实 Tauri 窗口中人工确认。
