# 设备工作台、自动化与 AI 操作设计规格

## 目标

在不删除或改变现有设备管理能力的前提下，把所有页面统一为已确认的 4 张 UI 设计图中的“紧凑工作台”体系，并增加可持久化的自动化脚本执行能力和带人工确认边界的 AI 设备操作能力。

## 已确认的视觉规范

- 顶部使用紧凑身份/状态栏；页面标题、连接状态、关键指标和主要动作在同一层级展示。
- 主内容使用白色工作面、浅灰背景、细分隔线、8px 左右圆角和青绿色主强调色。
- 页面不使用左侧大导航栏作为主要工作区；导航压缩为顶部标签或工作面内分段导航。
- 表格页使用高密度表格、行内操作、批量操作轨和状态反馈条。
- 复杂功能收进右侧操作 dock、可折叠 shelf 或底部反馈轨，避免把所有功能堆成大卡片。
- scrcpy 保持独立窗口；主界面只能展示截图预览、独立窗口状态和最近反馈，不能把 scrcpy 视频流嵌入主页面。
- 自动化与 AI 页面必须使用同一套工作台视觉语言，但不得照抄 escrcpy 的布局、组件命名或代码。

## 自动化脚本能力

自动化脚本是本地可导入/导出的 JSON 文档，脚本执行由 Rust 侧调度并复用现有 `DeviceService` 对应的 Tauri 命令，不绕过现有确认和错误反馈。

### 脚本模型

```ts
type AutomationStepType =
  | "tap" | "swipe" | "longPress" | "text" | "key"
  | "shell" | "wait" | "screenshot" | "record"
  | "launch" | "install" | "imageMatch" | "if" | "loop";

interface AutomationScript {
  id: string;
  name: string;
  description: string;
  version: 1;
  variables: AutomationVariable[];
  steps: AutomationStep[];
  createdAt: string;
  updatedAt: string;
}
```

每个步骤都必须保存稳定 id、类型、显示名称、执行前等待、执行后等待和可序列化参数。变量支持系统变量（设备 id、步骤索引、时间戳）和用户变量；敏感变量不得写入普通执行日志。

### 执行约束

- 单设备执行、选中多设备执行和全量设备执行必须使用同一调度器。
- 默认并发为 2，可在执行面板中设置上限；每台设备都有独立进度和错误状态。
- 支持运行、暂停、继续、停止、单步执行和失败重试。
- 识图步骤通过截图裁剪、阈值和匹配点生成判断结果；匹配失败必须可配置为跳过、停止或走条件分支。
- 脚本执行中的危险操作（关机、卸载、删除、Shell）必须在开始前或首次调用前明确确认，并在日志中标记。
- 执行记录包含脚本版本、目标设备、步骤结果、耗时、输出和错误，但不得泄露 API Key 或变量秘密。

## AI 操作能力

AI 功能参考 `Reference_Projects/escrcpy` 中 README 与 locale 对 Copilot 的能力描述，但采用本项目自己的 Tauri/React 边界和 UI 结构。参考目录中没有可直接移植的 Copilot 源码，因此只复用能力清单，不复制代码或页面。

### AI 边界

- AI 只通过一个受控工具注册表调用设备能力；工具参数先通过 schema 校验，再进入现有 Tauri 命令。
- 只读工具（设备信息、截图、应用列表、文件列表、日志查询）默认可执行。
- 写入或危险工具（输入、Shell、安装、卸载、删除、重启、关机、文件传输）默认需要用户确认。
- 每次任务拥有最大步数、单步超时、总超时、失败重试次数和取消信号。
- AI 对话、工具调用参数、用户确认、结果和错误都进入脱敏执行日志。
- 模型供应商使用用户设置的 OpenAI-compatible `baseUrl`、API Key、模型 id 和视觉能力标记；密钥只在 Rust 请求边界使用，不进入前端日志。
- 当未配置 AI 服务或当前模型不支持图片输入时，必须显示可理解的阻断原因，不影响普通设备功能。

### AI 工具第一批

设备列表、设备信息、截图、启动应用、停止应用、输入文本、按键、点击、滑动、音量、旋转、设备 Shell、应用列表、文件列表、上传文件、下载文件、系统日志查询。每个工具拥有名称、描述、参数 schema、风险级别和是否需要确认。

## 数据与兼容

- 现有设备、Docker、ADB、scrcpy、终端、日志、设置服务和提示文案保持原 API 与行为。
- 新增持久化优先放在应用数据目录下的独立 JSON/SQLite 命名空间，不能改变已有设置文件格式。
- UI 层只能通过新的 `automationService`、`copilotService` 和现有 `DeviceService` 访问能力，不直接调用 Rust 内部实现。
- 新增页面必须支持中英文；中文是源语言，英文必须提供对应键值。
- `Reference_Projects/` 仅作只读参考，不能加入 git、不能修改、不能把其 UI 代码复制进项目。

## 验收标准

1. 所有路由都能在统一工作台壳中渲染，并与对应设计图保持结构一致。
2. 现有全量测试和构建通过；每个新增服务、模型、调度状态和风险确认路径都有测试。
3. 自动化脚本可以创建、保存、导入、导出、单步执行、暂停/继续/停止、批量执行并查看日志。
4. AI 可以在配置模型后完成只读设备任务；写操作在确认前不会执行；取消、超时、错误和模型不支持视觉都有明确状态。
5. UI 运行截图和结构回归测试证明没有把 scrcpy 嵌入主窗口，也没有破坏已有页面功能。
