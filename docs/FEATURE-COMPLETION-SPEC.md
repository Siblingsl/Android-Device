# Redroid Device Center 功能完善规格

> 目标：在不改变 Docker、Redroid、ADB、Magisk/Root 现有业务逻辑的前提下，把项目从“运行环境管理器”完善为“Redroid 多设备控制中心”。

## 1. 现状与范围

当前项目已经具备 Dashboard、设备列表、设备详情、Docker/Redroid 实例、ADB、APK、数据卷、日志、设置、基础 scrcpy 生命周期和 Root/Magisk 能力。现有功能基线见 [README](../README.md)；本轮补齐了内嵌投屏、设备工作台、群控、文件/终端和自动化等缺失能力。

本规格只描述当前项目相对于 escrcpy 实际能力的补齐项。基础能力已存在但不完整的项目按“升级”处理，不重复建设。

参考依据：

- [escrcpy 功能说明](../Reference_Projects/escrcpy/README-CN.md)
- [escrcpy 设备操作](../Reference_Projects/escrcpy/docs/zhHans/guide/operation.md)
- [escrcpy 偏好设置](../Reference_Projects/escrcpy/docs/zhHans/guide/preferences.md)
- [escrcpy 里程碑](../Reference_Projects/escrcpy/docs/zhHans/guide/milestones.md)
- [窗口编排](../Reference_Projects/escrcpy/docs/zhHans/guide/window-arrangement.md)

### 不改变的既有能力

- Docker Desktop/WSL binder/Redroid 镜像和实例生命周期。
- ADB Server、设备连接、局域网 `/24` 扫描和已有批量基础操作。
- APK、数据卷、系统日志、设置保存和自动启动设备。
- Magisk、Zygisk、LSPosed、Shamiko、设备伪装和 Root 策略。

### 统一闭环要求

每个功能必须满足：入口 → 操作 → 进行中状态 → 成功/失败反馈 → 可回看结果或跳转到相关页面。危险操作需要确认，离线设备必须禁用需要 ADB 的操作并说明原因。

### 交互和视觉要求

- 采用“设备工作台”方向：页面用模块、工具栏、分隔线和状态行表达层级，不使用大面积卡片堆叠。
- 主内容保持紧凑；模块内部优先滚动，只有页面内容确实超出窗口时才出现页面大滚动条。
- 实时投屏是工作区的主视觉，设备控制、文件、应用、终端围绕设备上下文组织。
- 所有操作按钮有明确动词、禁用原因和键盘焦点；支持 `prefers-reduced-motion`。

## 2. P0：核心操作闭环

### P0-01 内嵌实时投屏

**目标**：在设备详情页内提供可操作的实时 scrcpy 画面，替代当前截图占位。

**涉及模块**：`DeviceDetail`、scrcpy 服务、设备会话状态、Tauri 前后端消息桥、投屏工作区样式。

**功能范围**：实时视频、页面内触控/鼠标/键盘、剪贴板双向同步、缩放、旋转、全屏、多 Display/虚拟 Display、断线重连、错误状态和页面内/独立窗口切换。

**验收标准**：

1. 在线设备打开控制页后 5 秒内显示实时画面；离线时不启动会话并显示原因。
2. 点击、长按、滑动、鼠标滚轮和键盘输入能在设备内生效。
3. 设备断开时画面进入“已断开”状态，重新连接后可以恢复，不产生僵尸进程。
4. 页面关闭或切换设备后，旧会话可以被停止或明确保留，scrcpy 状态与真实进程一致。
5. 原有截图、ADB 控制、启动/停止/重启 scrcpy 功能继续可用。

### P0-02 统一设备控制栏

**目标**：把现有 ADB 命令和新增 scrcpy 操作组织成统一控制栏。

**涉及模块**：控制栏组件、设备详情、设备列表行操作、设备服务。

**功能范围**：Home、返回、最近任务、锁屏、唤醒、熄屏、重启、音量、静音、旋转、通知栏、截图、录屏、安装 APK、启动应用、文件管理器、终端、网络供网、自定义 scrcpy；按钮拖拽排序、隐藏、折叠、悬浮和按设备保存配置。

**验收标准**：

1. 控制栏中的操作都能调用真实后端命令并反馈结果。
2. 用户调整顺序、隐藏按钮、折叠状态后，刷新页面仍保持。
3. 离线设备的 ADB 操作禁用并显示“需在线”。
4. 危险操作（重启、停止、清理等）有确认。

### P0-03 多设备群控

**目标**：让用户可以对选中的设备组同步执行操作。

**涉及模块**：设备选择模型、批量任务队列、群控状态面板、控制栏、文件/APK 服务。

**功能范围**：同步投屏、输入广播、批量截图、APK 安装、文件/目录推送、Shell、启动/停止/重启、应用启动、设备分组和失败重试。

**验收标准**：

1. 设备组中每台设备都有独立结果：成功、失败、跳过和失败原因。
2. 一台设备失败不阻塞其他设备，失败项可单独重试。
3. 广播输入不会把控制事件发送给未选设备。
4. 任务运行中可取消，取消后不再启动新设备任务。

### P0-04 完整文件管理器

**目标**：把当前基础文件列表升级为可持续使用的设备文件工作区。

**涉及模块**：文件列表、文件任务队列、上传下载后端、设备详情文件页。

**功能范围**：多选、批量复制/剪切/粘贴/移动/删除、重命名、新建文件、文本编辑、预览、面包屑、前进后退、收藏、快速访问、多文件/目录上传、拖拽上传、递归下载、进度/取消/重试。

**验收标准**：

1. 多选文件可以批量执行复制、移动、删除和下载。
2. 上传目录后远端目录结构保持不变。
3. 文件任务显示总进度、当前文件、速度、成功/失败数量，并可取消和重试。
4. 文件预览和编辑不会阻塞文件列表滚动；离线时操作禁用。

### P0-05 交互式终端

**目标**：提供真实的设备 ADB Shell 终端，同时支持本机终端。

**涉及模块**：终端页面、PTY 会话、ADB Shell 会话、窗口路由和设备控制栏。

**验收标准**：

1. `top`、`logcat` 等持续命令可以实时显示和中断。
2. 终端输入、输出、调整大小、复制粘贴正常。
3. 切换设备时不会把命令写入错误设备。
4. 关闭终端会话后后端进程被释放。

### P0-06 无线 ADB 配对与发现

**目标**：在现有局域网扫描上增加完整无线连接链路。

**涉及模块**：ADB 服务、无线连接弹层、保存的连接地址、配对状态。

**功能范围**：ADB Pair、配对码、二维码、mDNS 发现、IP/端口探测、USB 转 Wi-Fi、地址记忆、批量连接、自动重连。

**验收标准**：

1. 用户可输入配对地址和配对码完成配对，再连接设备。
2. 发现过程显示扫描、发现、探测、连接中、已连接和失败状态。
3. 已保存地址可以补全、重连和删除。
4. 现有 `/24` 扫描行为保持不变。

## 3. P1：效率和完整设备能力

### P1-01 录屏、录音和摄像头

补齐屏幕录制、音频录制、音视频录制、摄像头镜像、摄像头录制、摄像头选择、分辨率、比例、FPS、闪光灯、缩放、录制格式、方向、时长限制、自动播放和保存目录；OTG 输入补齐键盘、鼠标和游戏手柄模式选择。

**验收**：录制任务有开始/进行中/停止/成功/失败状态，生成文件可打开，设备断开能结束任务并保留错误原因。

### P1-02 高级 Scrcpy 配置

补齐最大分辨率、码率、FPS、编码器、缓冲区、裁剪、Display ID、方向、翻转、视频来源、摄像头分辨率/FPS、禁用视频/音频、音频来源/编码器/码率、保持设备音频、触摸点、熄屏超时、保持唤醒/活动、控制时熄屏、关闭时断电、不自动亮屏、虚拟 Display、Display 输入法策略、弹性 Display、虚拟 Display 内容保留、窗口尺寸/位置、背景色、无边框、置顶、屏幕保护、鼠标模式/绑定、键盘模式/注入策略和手柄模式。

**验收**：设置可以保存为全局默认、单设备覆盖和设备组配置；启动 scrcpy 时参数与界面值一致，非法参数在启动前提示。

### P1-03 Gnirehtet 网络供网

补齐安装检测、自动安装、启动/停止/重启、隧道状态、Relay、批量供网、自动修复、路径和参数配置。

**验收**：每台设备显示供网状态；失败时不显示成功，能看到命令输出和修复建议。

### P1-04 多窗口编排

补齐多设备网格、拖动、调整大小、自动排列、布局预览、保存/加载/重置、全局布局和单设备布局。

**验收**：设备上线后能按保存布局放置；窗口位置、尺寸和设备对应关系重启后可恢复。

### P1-05 应用管理增强

补齐应用选择器、控制栏快速启动、最近应用、收藏、应用图标/版本/权限/Activity、指定 Activity 启动、批量启停/清数据/卸载和桌面快捷方式。

**验收**：启动失败显示真实原因；批量应用任务逐设备显示结果；已有安装、启停、清数据和卸载保持可用。

### P1-06 设备资产信息

补齐设备名称/备注、标签、分组、筛选、历史离线设备删除、配置迁移、电池、电池温度、电源、电压、定时刷新、自动连接和自动投屏。

**验收**：自定义名称不改变 ADB Serial；离线设备可清理且不会误删 Docker 数据卷；状态刷新失败可见。

### P1-07 全局快捷键

补齐快捷键录入、冲突检测、设备/设备组绑定、投屏、录制、截图、终端、文件管理、显示/隐藏主窗口、脚本和供网快捷操作。

**验收**：快捷键在应用失焦时仍可用；冲突不能保存；禁用后不再触发。

### P1-08 托盘、开机启动和窗口集成

补齐系统托盘、关闭到托盘、托盘菜单、开机启动、启动自动连接/投屏、桌面快捷方式、边缘隐藏和边缘呼出。

**验收**：主窗口关闭到托盘后后台任务继续按设置运行；退出应用才结束进程；开机启动可关闭。

### P1-09 更新和配置迁移

补齐版本检查、更新说明、后台下载、进度、失败重试、用户确认安装、跳过版本、更新通道，以及全局设置/设备配置/快捷键/布局导入导出和版本迁移。

**验收**：更新失败不破坏当前版本；导入配置前预览覆盖项；旧配置可迁移并保留未知字段。

**发布前置条件**：Tauri updater 的 `endpoints`、签名 `pubkey`、各平台安装包和对应签名必须由发布流程提供。当前仓库保留空端点是为了避免把示例地址当成真实更新源；未配置时界面会明确提示开发构建不连接更新服务。正式包使用 `npm run tauri:build:release`，脚本会强制校验 HTTPS 端点和签名公钥后再把配置合并给 Tauri。

## 4. P2：自动化、AI 和平台扩展

### P2-01 键盘映射

补齐点击、摇杆、滑动、滚轮、自动化动作映射，按应用/设备保存，方案切换、导入导出和游戏输入。

**验收**：映射事件只作用于当前设备/当前应用；方案切换立即生效；配置可导入导出。

### P2-02 可视化自动化脚本

补齐点击、滑动、文字、按键、等待、启动应用、安装 APK、截图、录屏、Shell、条件、循环、变量、随机偏移、图片裁剪和图片匹配、模板、导入导出、单步执行、暂停/继续/停止、日志和批量设备执行。

**验收**：脚本每一步有状态和错误原因；暂停后不继续发送设备事件；批量执行隔离设备上下文；脚本可保存并再次运行。

### P2-03 定时任务

补齐定时启动/停止设备、启动应用、安装 APK、执行脚本、截图、录屏、Shell、按日期/星期/间隔执行、Cron、启停、历史、失败重试和日志。

**验收**：任务按本地时区执行；应用退出和重启后任务状态可恢复；同一任务不会重复并发执行。

### P2-04 AI / MCP 自动控制

补齐自然语言控制、多模型/API 配置、任务会话、工具确认、步骤限制、超时、设备/文件/应用/Shell/截图工具和多设备执行。

**验收**：所有有副作用的工具调用都可确认或拒绝；AI 失败不会继续执行后续危险动作；执行记录可回看。

**协议边界**：MCP 层至少需要实现 JSON-RPC 的 `initialize`、`tools/list`、`tools/call`、schema 校验、错误结果和确认策略；当前已增加 `rdc-mcp` stdio 服务入口，并由正式构建脚本把匹配当前 target triple 的服务二进制纳入 Tauri 包。默认只允许设备查询和截图，设备控制、Shell、APK 等副作用必须显式使用 `--allow-side-effects` 启动；生产环境仍应由 MCP 客户端负责进程生命周期和本机访问权限。

**本地启动**：`cargo run --manifest-path src-tauri/Cargo.toml --bin rdc-mcp --`；需要显式开放副作用时使用 `--allow-side-effects`，输入输出均为逐行 JSON-RPC 消息。正式包使用 `npm run tauri:build:release`，并必须提供 `RDC_UPDATE_ENDPOINT` 与 `RDC_UPDATE_PUBKEY`。

> 参考项目 README 说明部分高级功能来自私有 EscrcpyX 扩展，当前参考目录中的 Copilot、Automation、wscrcpy、madb 源码也不完整。因此本项按产品目标实现接口和安全边界，不直接假设参考仓库的实现可以复制。

### P2-05 macOS 支持

补齐 macOS 构建、ADB/Scrcpy/Gnirehtet 工具适配、权限、托盘、开机启动、窗口行为、安装包和更新。

**验收**：macOS 打包、安装、启动 Docker/ADB、连接设备和卸载流程可重复执行。

**运行边界**：本项目的 Redroid binder 内核方案依赖 Windows WSL 或 Linux 主机；macOS 不能直接复用该路径。macOS 要达到完整验收，必须先确定 Docker Desktop Linux VM、QEMU 自定义 Linux 或远程 Linux 主机中的一种 Redroid 运行方案，再补齐设备连接和安装包验收。

**macOS 工具适配**：GUI 启动时会优先解析 `/opt/homebrew/bin`、`/usr/local/bin`、Android SDK `platform-tools`、Docker Desktop CLI 目录和用户 `~/.local/bin`；仍可在设置中填写绝对路径覆盖自动解析结果。`.github/workflows/macos-package.yml` 提供 Intel 与 Apple Silicon 的原生测试和打包入口；运行正式打包前需在仓库配置 `RDC_UPDATE_ENDPOINT` 与 `RDC_UPDATE_PUBKEY` secrets。

## 5. 全局验收门槛

- P0 每项完成后必须通过：TypeScript 构建、Rust 检查、对应单元/集成测试、实际 Tauri 运行验收。
- P1 每项完成后必须通过：P0 回归、对应功能测试和至少一次真实设备/容器操作。
- P2 每项完成后必须通过：P0/P1 回归、任务取消/失败/重启场景测试和平台能力验证。
- 禁止留下空按钮、假成功、静态模拟结果、未接通的 TODO 或只改变视觉的占位实现。
- 所有新增异步任务必须具备取消、错误回传和资源清理路径。

### 实机验收前置条件

当前主机检测到 ADB 设备 `6d706def`，但状态是 `unauthorized`；Docker 客户端可用但 Docker Desktop 服务未连接；主机没有 Gnirehtet 二进制。因此内嵌投屏、交互终端、录制、无线配对、Gnirehtet 和真实多设备群控仍需在在线授权设备、Docker 服务和对应工具齐备后验收。已安装 `x86_64-apple-darwin` Rust 标准库并尝试交叉检查，但 Windows 主机缺少 Apple `cc` 工具链，无法替代 macOS 实机验收。

正式发布安全门禁：未配置 `RDC_UPDATE_ENDPOINT` / `RDC_UPDATE_PUBKEY` 时，`tauri-release-build.mjs` 按预期拒绝生成未签名发布包。
